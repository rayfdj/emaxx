### What the sjis/big5 batch does (for the commit message / review)

- decode-sjis-char / encode-sjis-char convert through the charsets of
  coding.c's Vsjis_coding_system = the LAST defined shift-jis system =
  japanese-shift-jis-2004.  So the primitives' kanji bank is JIS X
  0213 plane 1 (decode-sjis-char #x8940 → 38498; the euro sign,
  absent from 0208, ENCODES as #x8540 via JISX2131.map's 0x2921),
  while the `sjis' STRING codec belongs to japanese-shift-jis and
  stays on JIS X 0208.  The same bytes can answer differently between
  the primitive and decode-coding-string; both answers are GNU's own.
- encode-sjis-char applies JIS_TO_SJIS to whatever code the charset
  search returns — a katakana code 0x31 becomes 0x70AF (an invalid
  SJIS code).  Oracle-confirmed, reproduced faithfully.
- decode-big5-char reproduces coding.c's own bug: the second byte is
  masked with 0x7F before validation, so half of Big5 (#xA4A4
  included) signals "Invalid code" while encode-big5-char produces
  exactly those codes.
- Charset conversion gained `:superset` (jisx0213.2004-1 →
  jisx0213-a + jisx0213-1), on top of the previous batch's
  unify-charset state and `:subset` support.
- Disclosed, NOT fixed (ledger): (encode-sjis-char #xA5) ABORTS the

## Gate

The gate script lives in the session scratchpad (a /tmp path — it has
been REAPED by macOS once already).  If gone, recreate `gate.sh`:

```zsh
#!/bin/zsh
# Serial full gate: every unit test binary + integration tests, one log.
LOG=${1:?log path}
cd /Users/nbmhqa186/projects/emaxx || exit 1
export RUST_MIN_STACK=134217728
# Finding 113: the harness measures under LANG=C; the gate must too.
# (Before this was pinned, gates inherited the desktop's UTF-8 locale
# and five LANG=C-only reds were invisible.)
export LANG=C LC_ALL=C
{
  echo "=== gate start === $(date '+%F %T')"
  for stage in "lib:--lib" "bins:--bins" "integration:--test cli --test ert_runner"; do
    name=${stage%%:*}
    args=${stage#*:}
    echo "=== $name === $(date +%T)"
    eval "cargo test --profile gate $args" 2>&1
    echo "--- exit=$? ---"
  done
  echo "=== GATE DONE === $(date +%T)"
} >> "$LOG" 2>&1
passed=$(grep -E '^test result:' "$LOG" | sed -E 's/.* ([0-9]+) passed; ([0-9]+) failed.*/\1/' | paste -sd+ - | bc)
failed=$(grep -E '^test result:' "$LOG" | sed -E 's/.* ([0-9]+) passed; ([0-9]+) failed.*/\2/' | paste -sd+ - | bc)
{
  echo "=== gate finished $(date +%T) ==="
  grep -E '^test .* FAILED' "$LOG" | sed 's/^/    /'
  echo "TOTALS passed=$passed failed=$failed"
} >> "$LOG"
tail -8 "$LOG"
```

Launch: `nohup zsh gate.sh gate-vNN.log &`.  Takes ~1 h idle, up to
~3 h under desktop load (the lib stage alone was 9862 s in v60).
History: v59 2224/0 (thread batch), v60 2214/2 (both failures were

**The gate now runs `--profile gate`** (added 2026-08-28, after
finding 107 landed).  `[profile.gate]` in Cargo.toml inherits
`release` but keeps `debug-assertions` and `overflow-checks` ON —
those are the nets that have caught wrapped C-style index arithmetic
in ported code, and earlier gates were getting them only by accident
of `cargo test`'s dev default (at the crate's dev `opt-level = 1`).

## Probing discipline (hard-won, do not relearn)

- GNU decodes `--eval` argv with locale coding: use `-l FILE` or
  `\N{U+XXXX}` escapes for non-ASCII programs.
- Environment for shell probes: `LANG=C LC_ALL=C HOME=/nonexistent`.
  BUT the in-repo oracle helper (`assert_upstream_primitive_contract`)
  runs the oracle in the USER'S env (UTF-8): error messages get curly
  quotes and locale-dependent defaults differ.  Make test programs
  env-independent (bind `text-quoting-style 'straight`, setq-default
  buffer-file-coding-system nil) — see the file-coding test for the
  pattern.
- Contaminated-measurement trap: probe files listing symbols literally
  intern them; dump names + feed back as runtime strings.
- Raw CR/LF in probe output gets mangled by tail; print char-code
  lists instead.
